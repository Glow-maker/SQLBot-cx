## 六月兼容适配

- 使用六月 `dmgt_table.category_id` 绑定目录，不依赖新 `category.table_id`。
- Namespace 使用既有 `tenant_id` 列显式过滤，不增加 `is_default`。
- schema 从六月登记表名/数据源默认 schema 解析，不添加 `table.schema_name` 或 `table_comment`。
- 六月没有关系登记模块：关联为空，不引入 `dmgt_table_relation`、`source` 或关联推荐迁移。
- 已登记结构全部进入同步快照，包含隐藏字段和第21个之后的字段；不扫描业务库。缺少字段报告单表失败。
- 查询时复核当前租户 ENABLED/APPROVED/MOUNTED 目录；保留角色授权，并严格匹配数据源、schema、表ID/名称。匿名/租户错误不包装成具体无权表。
- 补上六月独立索引管理页面，按钮和接口统一要求 `dmgt:data-source:sync`；不自动授权。
- 一键/定时同步通过原 OAuth2 RPC 取得短期身份，仍依赖现场 system-server、Redis、用户状态及权限。
- 自动存储仅创建 `dmgt_index_sync_control`；已有表探测通过即读写，不自动 ALTER 历史表。

SQLBot 包含预先分片向量化、哈希增量、任务持久化/去重/恢复、最高片段分数聚合和RRF候选融合。普通问数仅向量化问题，正常候选上限50；空召回不回退全量目录。火箭及真实阶段进度清单随镜像一起交付。

## 限制和未完成验收

1. **真实登录到成功问数未验证。** 既有本地中台401仍是发布前必检项，本轮没有通过关闭认证或Gate回避它。
2. 没有部署这份六月JAR到真实Nacos/system-server/Redis环境；OAuth2 RPC、服务账号、现有字段/行权限、正常目录和其他数据源页面需现场联调。隔离MySQL只验证本次读取涉及的六月结构，不是整个平台系统测试。
3. 有权账号成功问数、无权账号拒绝后无SQL执行、跨schema/跨源、权限申请、窄屏阶段展示及成功收起/失败保留需对本包进行浏览器验收。现有自动化测试不能替代此项。
4. 真实业务代表性问题的必要表覆盖率95%、预热“问题向量化+召回”P95≤2秒是待测目标，没有实测达到结论。不承诺总问数时长已从30秒或一分钟降到特定秒数。
5. 原六月中台有不相关测试 `CategoryPermissionStrategyTest` 引用旧请求类型中不存在的 `setColPermissions`，本轮没有改动其他业务模型，而是将release模块测试编译限定为Sqlbot/IndexSync测试；没有运行全部中台测试，SpotBugs跳过。平台前端有既有Sass弃用提示，构建成功。
6. 容器健康探针接受受保护OpenAPI返回401，只表示HTTP应用已启动，不能证明认证链路正常；有效账号返回401仍必须修复。
7. PG兼容测试范围为PG17、MySQL为8.0.39。其他环境先报告差异并验证，不自动替换基础服务。

## 发布和回滚

按《内网升级操作教程》执行：核对/备份 → 中台配置与JAR → SQLBot迁移和镜像 → 中台静态资源及nginx → 手动首次同步 → 有权/无权验收 → 再启用自动同步。

旧Alembic不认识新增revision，回滚必须读《回滚教程》。保留新增表时需要受控调整版本记录；再次升级也需要核对表结构后处理版本记录，不能简单反复运行 CREATE。不要执行无关历史DDL或默认删表。
